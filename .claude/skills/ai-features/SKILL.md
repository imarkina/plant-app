## Безопасность — прежде всего
- Gemini вызывается только в Vercel edge-функциях. Никогда из браузера и из кода в `src/` клиента.
- Ключ `GEMINI_API_KEY` читается только из process.env и никогда не попадает в клиентский бандл.

## Как устроена фича
Путь: клиент → `POST /api/<имя>` (edge-функция в `api/`) → вызов Gemini в `src/server/<имя>.ts` → ответ клиенту.
Образец для новой фичи: `api/analyze.ts` и `src/server/analyze-plant-image.ts` — повторяй их структуру.

## Модель
- Имя модели gemini-3.6-flash, пока хардкодь строкой
- Промпты пиши на русском.

## Structured output
- Ответ модели всегда описывается Zod-схемой и передаётся в Gemini как `responseJsonSchema`.
- Новое поле в ответе — сначала добавь его в Zod-схему, потом в промпт.
- Ответ не прошёл схему — ошибка 502 по таблице «Ошибки». Непроверенный ответ никогда не отдавай клиенту и не сохраняй в базу.

## Ошибки
Клиенту — понятный текст без технических деталей. Детали — только в лог на сервере.

| Ситуация | Статус | Сообщение клиенту |
|---|---|---|
| Не картинка | 415 | Формат файла не поддерживается |
| Файл слишком большой | 413 | Файл слишком большой |
| Gemini: исчерпан лимит запросов (429) | 503 + `Retry-After: 60` | Сервис перегружен, попробуйте позже |
| Gemini: неверный ключ или регион | 500 | Внутренняя ошибка сервиса |
| Gemini: ошибка на их стороне или ответ не прошёл Zod-схему | 502 | Сервис недоступен, попробуйте позже |
| Gemini не ответил за 60 секунд | 504 | Превышено время ожидания |

## Лимиты
- Таймаут вызова Gemini: 60сек
- Фото перед отправкой: сделать ресайз, хелпер уже есть src/shared/image/resize.ts
- Если фича агентная (цикл с инструментами): не больше 6 шагов.

## Проверка перед «готово»
- Тесты не ходят в настоящий Gemini — замокать gemini api
- `npm run lint`, `npm test`, `npm run build` проходят.
